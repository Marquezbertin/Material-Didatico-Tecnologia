## ⚖️ Princípios (herdados do `docs/plano-pedagogico.md` do seu repositório `laboratorio-tech-social`)

1. **Gratuidade total** — nenhuma aula, material ou ferramenta pode ter custo para o aluno.
2. **Acesso aberto** — todo conteúdo é público e reutilizável (licença MIT).
3. **Aprender fazendo** — aulas baseadas em projetos, não em teoria pura.
4. **Inclusão** — acolher iniciantes, meninas e grupos subrepresentados na tecnologia.
5. **Segurança** — proteção de menores em primeiro lugar (ver `docs/seguranca-criancas.md`).

**Ciclo de cada módulo (do seu plano pedagógico):**

```
Apresentação do problema  →  Exploração  →  Mão na massa  →  Projeto  →  Mostra de resultados
```

- Aulas de **60 a 90 minutos**.
- Ritmo semanal (presencial ou online).
- Ferramentas gratuitas: Scratch, Python, Google Colab, GitHub Pages, Figma.
- Avaliação é **formativa**: projetos e participação, nunca prova eliminatória.

## 🛡️ Segurança e ética — LEIA ANTES DE AULA

O seu repositório `laboratorio-tech-social` tem um documento específico para isso:
`docs/seguranca-criancas.md`. Regras inegociáveis para aulas com menores:

- **Nunca publique dados pessoais reais de alunos** (nome completo, endereço, telefone, foto sem consentimento).
- **Nunca use e-mail institucional/pessoal de aluno** para cadastro em serviços externos sem autorização da escola e dos responsáveis.
- **Senhas de alunos**: use senhas descartáveis geradas para a aula e apague ao final.
- **Chaves de API (OpenAI, Gemini, Supabase)**: nunca no navegador de aluno em aula com dados reais — prefira a conta do professor ou variáveis de ambiente.
- **Relate qualquer situação de risco** conforme `docs/seguranca-criancas.md` do repositório.
- Cola de slides `site/slides/aula-criancas-*` já existe no repositório — use-a em vez de improvisar.

## 📌 Como este material foi construído

1. Leitura do arquivo `repositorios github.txt` da sua Área de Trabalho → link do seu GitHub.
2. Listagem dos **66 repositórios** públicos do seu perfil via API do GitHub.
3. Clone local de todos os repositórios e leitura do conteúdo real (READMEs, módulos, exercícios, código).
4. Mapeamento tema → repositório → módulo → arquivo de exercício.
5. Escrita do plano de aula usando **exclusivamente** esses arquivos como fonte.

Nenhum conteúdo de terceiros foi copiado; nenhuma aula foi inventada do zero.
